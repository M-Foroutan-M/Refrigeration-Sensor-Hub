# Networking — Raspberry Pi Sensor Hub (Ethernet / Wi-Fi / 4G)

## 0) Summary

This system uses a layered Linux networking stack:

```
Netplan (YAML) → NetworkManager (NM) → ModemManager (MM) → SIM7600 (QMI) → 4G
```

* **Netplan**: declarative config for interfaces; selects renderer
* **NetworkManager (NM)**: runtime connection manager (routing, DHCP, autoconnect)
* **ModemManager (MM)**: cellular control (SIM, APN, bearer/session)
* **nmcli**: CLI to control NM
* **mmcli**: CLI to inspect/control MM

Data interfaces:

* `eth0` → Ethernet
* `wlan0` → Wi-Fi
* `wwan0` → 4G data
* `cdc-wdm0` → modem control (QMI), not a data interface

---

## 1) File Locations

### Netplan

```
/etc/netplan/*.yaml
```

Defines interfaces and sets `renderer: NetworkManager`.

### NetworkManager (profiles)

```
/etc/NetworkManager/system-connections/*.nmconnection
```

Each connection profile (Ethernet, Wi-Fi, GSM) persists here.

### NetworkManager config

```
/etc/NetworkManager/NetworkManager.conf
```

### Logs

```
journalctl -u NetworkManager
journalctl -u ModemManager
```

---

## 2) Services

Check status:

```bash
systemctl status NetworkManager --no-pager
systemctl status ModemManager --no-pager
```

Restart if needed:

```bash
sudo systemctl restart NetworkManager
sudo systemctl restart ModemManager
```

## 4) Ethernet (eth0)

### Netplan (renderer = NetworkManager)

Example:

```yaml
network:
  version: 2
  ethernets:
    eth0:
      renderer: NetworkManager
      dhcp4: true
```

### NM profile (auto-generated by netplan)

Name typically: `netplan-eth0`

Inspect:

```bash
nmcli connection show netplan-eth0
```

Modify (requires sudo):

```bash
sudo nmcli connection modify netplan-eth0 connection.autoconnect yes
sudo nmcli connection modify netplan-eth0 ipv4.route-metric 600
```

Bring down/up:

```bash
sudo nmcli connection down netplan-eth0
sudo nmcli connection up netplan-eth0
```
